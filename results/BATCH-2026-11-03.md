## Question

Input fees are linear per input but rounded up per swap. Redeeming each token
separately pays that rounding every time. Can the vault drain redeem several
tokens in a single swap, and how much does it save?

## Setup

```sh
harness/mint/run-batch-demo.sh          # 4 tokens of 10 sat
BATCH_TOKENS=8 harness/mint/run-batch-demo.sh
```

1. Mint four 10 sat P2PK tokens to the seller (two proofs each: 8 + 2).
2. Verify each offline and accept it into the token vault: 8 journal rows,
   40,000 msat exposure.
3. Close all three databases (simulated crash).
4. Reopen; `SettlementWorker.settle_vault_batch(vault, batch_size=10)`.
5. The redeemer collects every proof from the batch, sets the seller key once,
   and calls `wallet.redeem(all_proofs)` — one `/v1/swap`.
6. NUT-07 checkstate all inputs.

## Measurements

| Metric | Value |
|---|---|
| Tokens | 4 × 10 sat |
| Inputs | 8 (2 per token) |
| Batches | **1** |
| Journal rows settled | **8/8** |
| Failed rows | 0 |
| Vault pending before → after | **8 → 0** |
| Exposure before → after | **40,000 → 0 msat** |
| Input fee, batched | **1 sat** |
| Input fee, one swap per token (estimate) | **4 sat** |
| NUT-07 inputs | **SPENT ×8** |
| Errors | none |

The estimate uses the batch's own input count and the advertised
`input_fee_ppk=100`: one swap with two inputs rounds to 1 sat, so four separate
swaps would pay 4 sat. The batch pays 1.

## Interpretation

1. **Batching works and saves the per-swap rounding.** 1 sat versus 4 sat for
   four tokens. The saving grows with the number of small tokens, not with the
   amount: the fee is per input, but the ceiling is per swap.
2. **One key setup per batch.** The redeemer signs every P2PK input with the
   seller key in one wallet session; no per-token wallet round trip.
3. **The vault makes the batch recoverable.** All eight rows were accepted
   before the crash and settled after the reopen, so batching does not weaken
   the crash guarantee.
4. **Batch size is a trade-off.** A larger batch saves more rounding but holds
   the exposure longer and makes one swap carry more inputs. The worker accepts
   `batch_size`; 10 is a reasonable lab default.

## Caveats

- One mint, one run, `FakeWallet`. The separate-fee number is an estimate from
  the advertised ppk, not a measured run of four separate swaps.
- The tokens are all locked to the same seller key; a batch across different
  lock keys would need per-input signing keys.
- The crash is simulated by closing the databases, not killing a process.
- The mint-token step is occasionally slow; the runner now caps each mint at
  120 s.
